SwanPanel User Guide

Welcome to the official documentation for SwanPanel, an enterprise-grade, zero-trust web control plane built for the industry-standard strongSwan IPsec VPN daemon.

SwanPanel was designed to eliminate the operational friction of traditional VPN administration: it eliminates static configuration editing, eliminates manual certificate authority management, and eliminates third-party client application requirements across mobile and desktop endpoints.

Prerequisites & System Requirements

SwanPanel runs on any standard Linux distribution with kernel IPsec support:

  • Supported Distributions: Ubuntu 22.04 / 24.04 LTS, Debian 12 (Bookworm), CentOS / RHEL 9, Rocky Linux 9, AlmaLinux 9, Fedora 39+.
  • Hardware: 1 CPU Core, 512 MB RAM, 100 MB disk space.
  • Network Ports:
    • UDP 500: IKEv2 Key Exchange
    • UDP 4500: NAT-Traversal (NAT-T)
    • TCP 8080 (or 443 via reverse proxy): Web Control Plane
    • UDP/TCP 53: Internal Split-DNS server

1-Line Automated Installation

Run the following command on your Linux server with root privileges:

curl -sSL https://raw.githubusercontent.com/thienvu18/swan-panel/main/install.sh | sudo bash

The script installs strongswan and strongswan-charon-plugin-vici, configures kernel forwarding, downloads the latest static swan-panel binary for your architecture, installs a systemd unit, and starts the service.

Accessing the Web Dashboard

After installation, navigate to http://<SERVER_IP>:8080 in your browser:

  • Initial Username: admin@swanpanel.internal
  • Initial Password: Admin@SwanPanel123

You will be prompted to change your administrative password immediately upon initial sign-in.

Environment Variables

SwanPanel configuration is managed via /etc/swan-panel/config.env:

# Application Environment (production / development)
APP_ENV=production

# HTTP Web Control Plane Binding
SERVER_PORT=8080
SERVER_HOST=0.0.0.0

# Security Secret (32-byte hex for JWT signing)
JWT_SECRET=your_cryptographically_secure_random_key_here

# strongSwan UNIX Socket
VICI_SOCKET=/var/run/charon.vici

# Split-DNS Engine
ENABLE_DNS=true
DNS_PORT=53

# Logging Level (debug, info, warn, error)
LOG_LEVEL=info

Apple Ecosystem Provisioning (macOS & iOS)

SwanPanel generates signed .mobileconfig XML profiles containing embedded PKCS#12 client certificates and the SwanPanel Root CA trust chain.

  1. Navigate to Resources & Devices in the SwanPanel web interface.
  2. Click + Add Device, choose Apple (macOS / iOS), and assign a hostname (e.g. alice-macbook).
  3. Click Download Profile (.mobileconfig).
  4. On macOS, double-click the downloaded profile. Open System Settings -> Profiles, click Install, and enter your local admin password.
  5. Your Mac will connect automatically via native IKEv2 whenever network connectivity is established.

Windows 10 & 11 Provisioning

SwanPanel auto-generates idempotent PowerShell scripts configuring the native Windows VPN subsystem:

# Example command generated by SwanPanel
Add-VpnConnection -Name "SwanPanel-VPN" `
  -ServerAddress "vpn.company.com" `
  -TunnelType IKEv2 `
  -AuthenticationMethod MachineCertificate `
  -SplitTunneling

Set-VpnConnectionIPsecConfiguration -ConnectionName "SwanPanel-VPN" `
  -AuthenticationTransformConstants GCMAES256 `
  -CipherTransformConstants GCMAES256 `
  -EncryptionMethod GCMAES256 `
  -IntegrityCheckMethod SHA384 `
  -PfsGroup ECP384 `
  -DHGroup Group14

Linux Provisioning

For Linux desktop endpoints, SwanPanel delivers ready-to-import NetworkManager connection files (.nmconnection):

# Move profile to NetworkManager configuration directory
sudo cp SwanPanel.nmconnection /etc/NetworkManager/system-connections/
sudo chmod 600 /etc/NetworkManager/system-connections/SwanPanel.nmconnection

# Reload and connect
sudo nmcli connection reload
sudo nmcli connection up SwanPanel

Android Provisioning

Android devices connect natively using standard IKEv2 RSA certificate authentication:

  1. Download the .p12 bundle from SwanPanel onto the device.
  2. Go to Settings -> Security & Privacy -> Encryption & Credentials -> Install a Certificate -> VPN & App User Certificate.
  3. Select the downloaded bundle and enter the bundle password displayed in the SwanPanel UI.
  4. Open VPN Settings, create a new connection with Type IKEv2/IPSec RSA, and select the installed certificate.

Zero-SSH strongSwan Control Plane

SwanPanel manages strongSwan entirely through its official VICI protocol (govici) over the UNIX socket /var/run/charon.vici:

  • RAM Dynamic Reloads: When configuration parameters or policies change, SwanPanel issues load-conn commands directly to strongSwan's memory. Active tunnels are never dropped or interrupted.
  • Instant SA Termination: When an administrator revokes a device or terminates a session, SwanPanel dispatches a terminate command to immediately tear down the active IKE Security Association in the Linux kernel.

Split-DNS & MagicDNS Engine

The integrated DNS engine runs on UDP/TCP port 53 and eliminates DNS leaks while resolving private service hostnames:

  • MagicDNS: Automatically maps <device-hostname>.strongnet to the client's internal IP address.
  • Custom DNS Overrides: Define custom A or CNAME records (e.g. gitlab.internal -> 10.60.0.50) in the DNS Engine management tab.
  • Recursive Upstream Forwarding: External domain queries (e.g. github.com) are resolved via configured upstream servers (default: Cloudflare 1.1.1.1 and Google 8.8.8.8).

Zero-Trust Access Policies

SwanPanel separates network permissions into User Groups and Resource Groups:

  • Create User Groups (e.g. Developers, DevOps, Contractors).
  • Create Resource Groups defining IP subnets (e.g. Production VPC: 10.60.10.0/24, Staging: 10.60.20.0/24).
  • Attach ALLOW or DENY rules between groups. The Policy Compiler compiles these rules into explicit traffic selectors and firewall exclusion filters.

Production Hardening & Reverse Proxy

For production deployments, place SwanPanel behind a reverse proxy handling TLS termination.

Example Caddy Configuration

vpn.yourdomain.com {
    reverse_proxy localhost:8080
}

Firewall Configuration (UFW)

# Allow IPsec VPN traffic
sudo ufw allow 500/udp
sudo ufw allow 4500/udp

# Allow HTTPS control plane
sudo ufw allow 443/tcp

# Enable NAT masquerade for client subnet
sudo iptables -t nat -A POSTROUTING -s 10.60.0.0/16 -o eth0 -j MASQUERADE

Troubleshooting & FAQ

strongSwan Daemon Disconnected

Ensure the charon.vici plugin is enabled in /etc/strongswan.d/charon/vici.conf and the strongSwan service is active (sudo systemctl restart strongswan).

Client Connection Timeout

Verify that UDP ports 500 and 4500 are not blocked by cloud provider security groups (AWS Security Groups, Hetzner Firewall, GCP Firewall Rules).
