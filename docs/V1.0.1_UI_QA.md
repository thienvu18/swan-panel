### Screen-by-screen verification breakdown

1. **Dashboard**
   - Typography: Balanced density (`.app-content table`, line-height 1.5, `min-h-[2rem]` action targets) eliminates clipped numbers while preserving tabular efficiency.
   - Uptime formatting: `formatDuration` converts raw seconds (`8100s` -> `2h 15m`, `90061s` -> `1d 1h`); raw gateway values remain accessible in tooltips.
   - Missing metrics: Error / missing states display `Unavailable` / `—` rather than misleading zero metrics.
   - Accessibility: Sessions table container exposes `tabIndex={0}`, `role="region"`, `aria-label`, and `aria-describedby="dashboard-session-scroll-hint"` for keyboard-only horizontal scrolling.

2. **Resources / Add Subnet**
   - Touch ergonomics: Form inputs and native select elements meet the minimum 38px height (`min-h-[2.375rem]`).
   - Usable capacity preview: `/24` preview correctly calculates $2^{(32 - 24)} - 3 = 253$ usable client VIP addresses (network, gateway loopback, and broadcast reserved).
   - Validation & overlap guards: `previewSubnet` blocks out-of-range masks (`/31`, `/7`) and octets > 255; `subnetOverlaps` detects intersecting CIDRs against existing resource groups and disables the Save action.
   - Mobile legend: `TableActionLegend` renders on narrow widths (`lg:hidden`) with readable text labels for Download Profile and Revoke actions.

3. **Resources / Add Device**
   - Company Node segregation: Modal switches between Company Node and User Device. Selecting Company Node automatically clears owner selection and hides the user selector.
   - User Device requirement: Selecting User Device requires an active employee account with an explanatory hint (`resources.owner_required_hint`) and disables submission until assigned.
   - Profile & revoke actions: Download profile and certificate revocation retain localized tooltips, accessible labels, and confirmation dialogs.

4. **Users / User Groups**
   - Primary contextual actions: Add User is the primary contextual action on the Directory tab; Add Group is the primary contextual action on the User Groups tab.
   - Empty and search states: Empty groups table and filtered search results render translated `EmptyState` actions with clear next steps.
   - Narrow viewport discoverability: `TableActionLegend` identifies icon-only actions (Grant Admin, Reject/Approve, Delete) on mobile and touch devices.

5. **Access Rules / DNS / OIDC**
   - Distinct table states: Tables across all management views use `TableQueryState` providing distinct loading spinners, localized empty states, and explicit error banners with retry triggers.
   - DNS filter chips: Filter bar chips list All, A, and CNAME records with live counts.
   - Action focus & confirmations: Focus rings (`outline: 2px solid #3b82f6`) and `[data-tooltip]:focus-visible` ensure keyboard visibility. All destructive actions require confirmation dialogs with variable interpolation.

6. **OIDC**
   - Canonical callback disclosure: With a public HTTPS URL configured, the displayed redirect URI matches the server-authoritative callback URL.
   - Production validation: When no valid public callback URL is configured, a warning is rendered and adding a new IdP is blocked.

7. **Server Settings / Advanced**
   - JSON editor alignment: `AdvancedJSONEditor` aligns syntax-highlighted code, line numbers, and transparent native textarea cursor across both vertical and horizontal scrolling.
   - Client-side validation: `checkGatewayJSON` validates supported keys, primitive types, and valid MSS clamping ranges (0 or 500–8960), blocking Save & apply on malformed input.
   - Visual change diff: Differences between active and edited configurations render in a readable comparison table.
   - Reset safety: Resetting to saved configuration requires explicit user confirmation if dirty.

8. **Server Settings / CA**
   - Read-only identity display: Current Root CA identity is presented as read-only description lists (`<dl>`, `<dt>`, `<dd>`) with copy controls.
   - Rotation separation: New CA parameter inputs appear only within a collapsible rotation section.
   - Guardrails: CA rotation is blocked when enrolled devices exist; when allowed, it requires typing `ROTATE CA` and confirming the modal dialog.

9. **System Logs**
   - Telemetry fallbacks: Unavailable PID and memory telemetry render as `Unavailable` instead of `0` / `0 MB`.
   - Readable durations: Daemon uptime renders in human-readable compact form (e.g., `5d 12h`).
   - Live stream & pause: SSE stream dynamically invalidates logs while live; pausing stops queries and preserves the current terminal snapshot without resetting scroll position.

3. **Technical Note on Native OS `<select>` Dropdown Menus:**
   - Browsers in headless Chromium mode (`--headless=new`) render DOM nodes via the software compositor without an operating system windowing manager. Consequently, native OS popover menus (such as the OS-level dropdown popup list spawned by native HTML `<select>` elements in `12_modal_add_rule_device_select_open.png`, `12_modal_add_rule_subject_select_open.png`, and `14_modal_add_dns_override_record_type_open.png`) are not captured into screenshot pixels.
   - Manual QA verification confirms that keyboard and click focus properly activates native dropdown menus across macOS, Windows, and Linux. The captured screenshots faithfully record the focused element state (`[id="access-rule-subject"]:focus`), blue focus ring, and active input validation.
